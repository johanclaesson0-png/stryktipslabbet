# V34: startelvor, skador och avstängningar
Manual intake: `data/v34/manual/<draw>.json` with schema `v34-team-news-intake-v1`, draw_number, reg_close_time and entries. Each entry: number, exact home/away strings, kickoff (timezone), side, exact team, checked_at and reported_at (timezone), publisher, HTTPS source_url, review_method=manual_source_review. For lineup: type=lineup, status=confirmed or predicted, players=[11 unique names]. For absence: type=absence, player, status=out/suspended/doubtful/available, reason. Only record what the linked source actually supports, use real check/publication times, never invent information. Empty entries means unknown, not healthy. If publication time is not supplied do not mark a fabricated time as reported. Conflicting facts held out.
Provider: existing APIFOOTBALL_KEY and PLAYER_DATA_PUBLICATION_APPROVED=1 required; do not commit key or assume rights. No network calls on PR config check. Main workflow attempts a morning collection and a late collection (last 20 min, at least 3 min remaining). Each attempt <=35 requests, V17 roster requests skipped on the cutoff UTC date when provider is enabled. GitHub schedule can be delayed, so late lineup fetch isn't guaranteed. Provider-listed XI distinct from independently confirmed XI. Match 1 is later and ordinary lineup window is after the cutoff. Provider empty injury list never implies health. Latest official fixture pair and kickoff validated. Automatic provider data may not be available in all leagues or plans.
Public: truppkoll.html and links from current V33 comparison. No numerical model changes, player effect or xG assumptions. Existing manual player sensitivity calculator is separate and uncalibrated. On cutoff day inspect official club news, then team sheets, fill the manual file with source-backed entries if provider not configured. Main workflow publishes on merge or schedule. No bets submitted.
